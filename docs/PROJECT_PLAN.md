## 一、项目目标与验收标准

### 最终交付物

一个可以**现场演示**的系统:

```
[Hi3516DV300 开发板]                          [PC]
  GC2053 摄像头                                 VLC / Qt 客户端
       ↓                                          ↑
  MPP 采集编码 (H.264/H.265)                      │
       ↓                                          │
  自研 RTSP/RTP 服务端 ──── 以太网 ────→ 实时画面
       ↓
  OSD 时间叠加
       ↓
  MP4 录制 → TF 卡(环形覆盖)
```

### 验收标准(逐条可测)

| # | 验收项 | 判定方法 |
|---|---|---|
| A1 | PC 用 VLC 打开 `rtsp://<板子IP>:554/live` 能实时看到画面 | 肉眼观察,延迟 < 1s |
| A2 | 至少 2 个客户端可同时拉流 | 开两个 VLC 窗口 |
| A3 | 画面右上角有实时时间叠加(OSD) | 肉眼观察,秒级更新 |
| A4 | 能自动录制 MP4 到 TF 卡,文件可用 VLC 播放 | `ls /mnt/sdcard` + PC 播放 |
| A5 | 录制支持环形覆盖:写满后自动删最旧 | 连续录到超过容量上限,检查文件数稳定 |
| A6 | 录制过程被强制中断,已关闭的分段仍可播放 | kill 进程后检查之前的分段 |
| A7 | 客户端断开/重连不影响服务端和录制 | 反复开关 VLC |
| A8 | PC 客户端能实时显示 + 回放已录制文件 | 界面操作 |

> **简历可用线**:A1~A3 + A4 + A7 完成即"完整可讲"。
> A5/A6/A8 是加分项。

## 三、技术架构

### 3.1 数据流

```
GC2053 ─MIPI CSI─→ VI ─→ VPSS ─┬─→ VENC ch0 (H.265 1080p30)
                                └─→ VENC ch1 (H.264 720p30)
                                      │
                                      ▼
                          Annex-B 码流 (sps/pps/sei/idr/slice…)
                                      │
                          ┌───────────┴───────────┐
                          ▼                       ▼
                   nalu.c 解析             (M3) MP4 录制
                          │                  mp4v2 + 环形覆盖
                          ▼
                   发送队列(环形缓冲)
                          │
                          ▼
                   rtp.c 打包 (FU-A)
                          │
                          ▼
                   UDP sendto ──→ PC 客户端
                          ▲
                          │
              rtsp.c 控制信令(epoll 事件循环)
```

### 3.2 线程模型

| 线程 | 职责 | 关键约束 |
|---|---|---|
| **主线程** | MPP 初始化、启动子线程、等待退出 | — |
| **net 线程** | `epoll` 同时监听:VENC fd + RTSP listen fd + 各客户端 fd | **绝不阻塞** |
| **发送线程** | 从队列取 NALU → RTP 打包 → `sendto` | 网络慢不能拖累取流 |
| (M3) 录制线程 | 从队列取 NALU → mp4v2 写文件 | 磁盘慢不能拖累取流 |

**核心设计思想:采集、发送、录制三者解耦**,任何一环变慢都不影响其他环。

**M1-4 SDP 是最大风险点**。SDP 写错一个字段 VLC 直接"无法播放"。要用实测数据填:

```
实测可用数据:
  H.264: sprop-parameter-sets = Base64(SPS) + "," + Base64(PPS)
         SPS 15 字节, PPS 4 字节
  H.265: sprop-vps/sps/pps
         VPS 23, SPS 35, PPS 9 字节
  分辨率: 1080p(H.265) / 720p(H.264)
  帧率  : 30.000 fps   ← 2026-09-14 实测修正(原写 25fps,与本文件第 170 行自相矛盾)
                         来源:MP4 `stts` 每帧间隔 512 单位 ÷ `timescale` 15360
                         = 30.000000 fps;帧数 734 / 时长 24.473 秒
                         (见 `docs/问题与解决记录.md` B011)
  payload type: 96(H.264) / 97(H.265)
```

> ⚠️ **参数集字节数(实测,直接决定 `sprop-parameter-sets` 的内容)**:
> ```
> H.264 chn1: SPS 15 B + PPS  4 B
> H.265 chn0: VPS 23 B + SPS 35 B + PPS  9 B
> ```
> 上面那行 `VPS 23, SPS 35, PPS 9` 是**对的**;
> `docs/面试问答.md` Q07 原先写的 H.264 PPS 5 / H.265 PPS 10 是错的,**已修正**。
> **这几个字节错一个,VLC 就是"无法播放",而且不告诉你哪里错。**

**M1-9 联调排错顺序**(很重要,照这个顺序查效率最高):
1. VLC 连不上? → 先 `telnet <ip> 554` 确认端口在听
2. 连上但不播? → 抓包看 `DESCRIBE` 的 SDP 是否被 VLC 接受
3. 播了但花屏? → 检查 SPS/PPS 是否随 IDR 一起发(实测每个 IDR 前都有)
4. 播了但卡顿? → 检查分片发送速率 / 队列是否溢出

### M3 — MP4 录制 + 环形覆盖

| 任务 | 内容 |
|---|---|
| M3-1 | `record.c`:mp4v2 封装单个 MP4 |
| M3-2 | 分段录制:按起始时间命名 `年-月-日-时-分-秒.mp4` |
| M3-3 | 环形覆盖:容量/文件数上限,写满删最旧 |
| M3-4 | **优雅关闭**:捕获 SIGINT/SIGTERM,确保写 `moov` |
| M3-5 | 断电保护:缩短单段时长(降低损失面) |
| M3-6 | SD 卡写入性能验证(1080p 够不够) |

**对齐参考实现的规格**(从 TF 卡上的旧文件分析得到):

| 参数 | 值 |
|---|---|
| 编码 | H.264 1280×720 @30fps |
| 码率 | ~4 Mbps |
| 分段 | 按时间命名,单段 2~4 分钟 |
| 单段大小 | 22~115 MB |

**⚠️ 这是本项目最能体现工程能力的地方**:
TF 卡上 4 个旧文件里**有 1 个残缺不可播**(没写 `moov`)。
参考实现没处理好中断。**你处理好了就是加分项**,面试可以专门讲。

### M4 — PC 拉流端

| 任务 | 内容 |
|---|---|
| M4-1 | PC 装 Qt Creator + FFmpeg 开发库 |
| M4-2 | FFmpeg 拉 RTSP 流 + 解码为 YUV/RGB |

## 十、简历包装建议

原项目描述里 **IMX6ULL 那一半你不做**(没板子),这是合理的**技术选型调整**,不是减分项。建议改成:

> **推流端**:基于 Hi3516DV300 + 海思 MPP 搭建 VI→VPSS→VENC 通路,自研 RTSP/RTP 服务端
> (epoll 多路复用 + 多线程),实现 H.264 NALU 的 FU-A 分片与 UDP 传输;
> 使用 REGION 模块实现 OSD 时间叠加;基于 mp4v2 实现 MP4 分段录制与环形覆盖存储。
>
> **拉流端**:考虑器件可得性,将原方案的 IMX6ULL 离线端改为 PC 端,
> 基于 Qt + FFmpeg 完成 RTSP 拉流、H.264 软解与实时显示。

**面试时的加分讲述点**(这些是真做过才讲得出的):
- 排查出 SDK 的 `SAMPLE_COMM_VI_GetComboDevBySensor()` **不含 GC2053 分支,恒返回 0**,导致 MIPI 设备号错误
- 发现 SDK 的 autotools 构建脚本**漏了 `atom_vp09.cpp`**,改用 CMake 才编过
- 设计 RTP 分片时**先用本机 UDP 自发自收做逐字节重组验证**,而不是直接拿 VLC 试
- 分析参考实现的录像文件,发现**中断时 `moov` 未写入导致不可播**,据此设计优雅关闭
